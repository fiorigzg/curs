# Аналитический движок (Stage 5) — математика и допущения

Документ описывает каждую формулу подсистемы риск-менеджмента и портфельной
аналитики, а также все принятые допущения. Чистые функции реализованы в
`packages/finance-core` (без I/O), оркестрация — в `apps/workers/src/curs_workers/analytics.py`,
подготовка данных — в `apps/api/src/curs_api/services/analytics_data.py`.

---

## Общие допущения

| Допущение | Значение | Почему |
|---|---|---|
| Тип доходностей | **простые** дневные `r_t = P_t / P_{t-1} − 1` | совместимость с CAPM-литературой (доходность портфеля = взвешенная сумма доходностей активов) |
| Торговых дней в году | **252** | стандарт индустрии |
| Аннуализация доходности | арифметическая: `r_год = r̄_дн · 252` | согласованность с CAPM (ожидания линейны) |
| Аннуализация волатильности | `σ_год = σ_дн · √252` | независимость дневных приращений |
| Базовая валюта | **₽ (RUB)** | приложение оценивает портфель в рублях; все доходности считаются в ₽ (нативные цены переводятся по дневному курсу ЦБ) |
| Минимум наблюдений | **30** дней | при меньшем числе рыночные метрики не считаются (`insufficient_data: true`) |
| Дивиденды | учитываются через **adjusted close** | total-return доходности |
| Окно истории | **≈1.5 года** (≈380 торговых дней) | скользящее окно, см. `price_history.WINDOW_DAYS` |

> Замечание о валюте: цена fiat-актива (USD/EUR) в системе — это его курс к рублю.
> Нативная `adj_close` актива умножается на курс его валюты к ₽ на ту же дату
> (протяжка назад), поэтому беты, корреляции и оптимизация считаются в одной
> валюте, согласованно с оценкой портфеля.

## 1. Adjusted close (total return)

Файл: `finance_core/adjust.py`. Метод обратной мультипликативной корректировки
(CRSP / Yahoo Finance):

```
factor_t   = 1 − D_t / close_{t−1}            (в день экс-дивиденда D_t)
adj_close_d = close_d · ∏_{t : ex_date_t > d} factor_t
```

Исторические цены умножаются на накопленное произведение **будущих** дивидендных
факторов; последняя цена (после всех дивидендов) равна raw close. Доходность,
посчитанная по `adj_close`, включает реинвестирование дивидендов.

Допущения и краевые случаи:
- дивиденды с неизвестной/нулевой ценой предыдущего дня игнорируются (factor = 1);
- дивиденд ≥ цены — аномалия, пропускается;
- крипта и фиат дивидендов не имеют → `adj_close = close`;
- ex-дата для T-Invest берётся как `recordDate` (упрощение: реальная экс-дата
  ≈ `lastBuyDate` + 1 торговый день — для корректировки этого достаточно).

## 2. Безрисковая ставка

Файл: `finance_core/capm.py :: daily_rf_from_annual`.

```
r_f,дн = (1 + r_f,год)^(1/252) − 1
```

Источники (таблица `risk_free_rates`, регион):
- **RU** — ключевая ставка ЦБ РФ (`cbr.key_rate`), дефолт `0.16`. Используется как
  базовая, т.к. портфель оценивается в ₽.
- **US** — 3M T-bill; интеграции с FRED нет, поэтому по умолчанию берётся
  `ModelParams.risk_free_usd` (дефолт `0.045`). Документируется как допущение.

В расчётах используется последняя известная ставка RU (fallback US, затем `0.16`).

## 3. По-активные метрики (`per_asset`)

Файл: `finance_core/capm.py :: capm_metrics`. Для каждого актива портфеля:

- **Средняя дневная доходность** `r̄_i` и аннуализированные `r_i,год = r̄_i·252`,
  `σ_i,год = σ_i,дн·√252` (выборочное стандартное отклонение, ddof=1).
- **Бета к рынку:**
  ```
  β_i = Cov(r_i, r_m) / Var(r_m)
  ```
- **Альфа Дженсена** (по регрессии `(r_i − r_f) = α + β·(r_m − r_f) + ε`):
  ```
  α_i = E(r_i) − [ r_f + β_i · (E(r_m) − r_f) ]
  ```
  Возвращается дневная (`alpha_daily`) и аннуализированная (`alpha = alpha_daily·252`).
- **R²** регрессии актив–рынок — доля дисперсии `r_i`, объяснённая рынком.
- **Идиосинкратическая волатильность** — `σ(ε_i)·√252`, где `ε_i` — остатки регрессии.

Краевые случаи: `< 30` наблюдений или `Var(r_m) = 0` → `insufficient_data: true`,
бета/альфа/R²/idio = `null`.

Рыночный бенчмарк портфеля = бенчмарк актива с наибольшим весом (по умолчанию
IMOEX). Подбор: crypto → BTC, USD-листинги → SP500, прочее → IMOEX.

## 4. Риск портфеля и стресс-тест (`risk`)

Файл: `finance_core/risk.py`.

- **Бета портфеля:** `β_p = Σ w_i · β_i` (None-беты считаются нулевыми).
- **Сценарий «рынок упал на X%»** (X ∈ {−5, −10, −20, −30, custom}):
  - **модельная оценка (CAPM):** `падение ≈ β_p · X` — линейная чувствительность;
  - **эмпирическая оценка:** средняя доходность портфеля в дни, когда рынок падал
    не меньше |X| (если таких дней < 3 — берётся общая условная оценка по худшим
    `K%` рыночным дням).
- **Условная оценка (conditional drop, CVaR-подобно):** средняя доходность портфеля
  в худшие `K%` (по умолчанию 5%) исторических рыночных дней.

Выдаются **обе** оценки — модель vs эмпирика (`scenarios[].model` и `scenarios[].empirical`).
`insufficient_data` при < 20 дней.

> Замечание: модельная оценка — гипотетический мгновенный шок рынка на X%, а
> эмпирическая считается на дневных доходностях, поэтому для крупных |X| (−20/−30%)
> эмпирических дней обычно нет (дневное падение такого размера крайне редко) —
> тогда показывается общая условная оценка по худшим 5% дням.

## 5. CAPM / SML / CML (`capm`)

Файл: `finance_core/capm.py`, `finance_core/optimize.py`.

- **SML (линия рынка ценных бумаг):**
  ```
  E(r) = r_f + β · (E(r_m) − r_f)
  ```
  Возвращаются точки `(β_i, E(r_i))` по активам, точка рынка `(1, E(r_m))` и
  параметры линии `{intercept = r_f, slope = E(r_m) − r_f}`.
- **CML (линия рынка капитала):** из `(0, r_f)` через касательный портфель
  `(σ_T, E(r_T))`:
  ```
  E(r) = r_f + Sharpe_T · σ,    Sharpe_T = (E(r_T) − r_f) / σ_T
  ```
  Возвращаются параметры линии и точки активов `(σ_i, E(r_i))`.

Касательный (max-Sharpe) портфель — см. §7.

## 6. Корреляции (`correlation`)

Файл: `finance_core/correlation.py`.

- **Матрица корреляций Пирсона** дневных доходностей (последний снапшот),
  `numpy.corrcoef`, диагональ = 1, NaN → 0.
- **Скользящая 60-дневная корреляция** для топ-K (=3) самых коррелированных пар
  (по модулю) — ряд для графика во времени.

## 7. Парные метрики (`pairwise`)

Файл: `finance_core/regression.py`, `finance_core/optimize.py`. Для каждой
упорядоченной пары `(A, B)`, `A < B` (таблица `pairwise_metrics`):

### (a) Парная регрессия с контролем рынка
```
r_A = α + β_B · r_B + β_M · r_M + ε
```
OLS (numpy), сохраняются `α, β_B, β_M, R², σ(ε)`, p-values (через t-распределение,
`scipy.stats.t`), флаг `singular` при коллинеарности (используется псевдообратная).
Высокий R² → кандидат на пару-заменитель (pair trading).

### (b) Двух-активная оптимизация (закрытые формы)
- **Min-variance** доля A:
  ```
  w_A* = (σ_B² − ρ·σ_A·σ_B) / (σ_A² + σ_B² − 2·ρ·σ_A·σ_B)
  ```
- **Max-Sharpe** доля A (с r_f), `Cov = ρ·σ_A·σ_B`:
  ```
  w_A* = [E_A·σ_B² − E_B·Cov] / [E_A·σ_B² + E_B·σ_A² − (E_A+E_B)·Cov],
  E_A = μ_A − r_f,  E_B = μ_B − r_f
  ```
Сохраняются оба набора весов, получившиеся σ, доходность, Sharpe.

### (c) Hedge ratio (OLS)
```
h = Cov(r_A, r_B) / Var(r_B)
```
Шорт `h` единиц B на 1 единицу A минимизирует дисперсию хеджированной позиции
`r_A − h·r_B`. Сохраняются `h` и достигнутое снижение дисперсии
`1 − Var(r_A − h·r_B)/Var(r_A)`.

## 8. Оптимизация портфеля (`optimization`)

Файл: `finance_core/optimize.py`. Входы аннуализированы (`μ×252`, `Σ×252`).

- **Портфель минимальной дисперсии** (long-only по умолчанию):
  - закрытая форма (если разрешены шорты): `w = Σ⁻¹·1 / (1ᵀΣ⁻¹·1)`;
  - long-only: QP через `scipy.optimize` (SLSQP), `Σw=1`, `w≥0`.
- **Касательный (max-Sharpe) портфель:**
  - закрытая форма: `w ∝ Σ⁻¹(μ − r_f)`, нормировка на `Σw=1`;
  - long-only: максимизация `(wᵀμ − r_f)/√(wᵀΣw)` (SLSQP).
- **Эффективная граница:** для сетки целевых доходностей решается min-variance при
  `wᵀμ = target` (long-only — SLSQP; шорты — закрытая форма Мертона). Точки
  возвращаются отсортированными по риску; отмечаются min-var и tangency портфели.
- **«Лучшая комбинация»** = веса max-Sharpe на всех активах портфеля (доходности с
  дивидендами уже учтены через adj_close).

При вырожденной `Σ` (коллинеарность) используется псевдообратная (`pinv`).
Флаг `allow_short` доступен в функциях; в пайплайне по умолчанию long-only.

## 9. Monte Carlo (`monte_carlo`)

Файл: `finance_core/mc.py`. Горизонт `H` (по умолчанию 252 дня), `N` путей
(по умолчанию 10 000). Потолки: `N ≤ 50 000`, `H ≤ 2 520` (защита от runaway).

- **Параметрический MC:** доходности активов ~ MVN(μ, Σ) дневные. Доходность
  портфеля — линейная комбинация `wᵀr`, поэтому распределена как
  **`N(wᵀμ, wᵀΣw)`**. Симулируем дневные доходности портфеля из этого одномерного
  нормального (математически эквивалентно полному MVN на уровне портфеля, но без
  `O(N)` памяти на путь) и компаундируем `V_{t+1} = V_t·(1 + r_t)`.
- **Исторический bootstrap MC:** ресэмплинг наблюдённых дневных доходностей портфеля
  с возвращением.

Выходы (для обоих методов): распределение конечной стоимости, перцентили
(5/25/50/75/95) — fan chart по шагам, **VaR(95%, 99%)**, **CVaR / Expected Shortfall**,
вероятность убытка `P(V_H < V_0)`, подвыборка путей для графика.

Определения (на доходности к стартовой стоимости `term_ret = V_H/V_0 − 1`):
```
VaR(95%)  = −quantile_5%(term_ret)            (положительное = убыток)
CVaR(95%) = −mean( term_ret | term_ret ≤ quantile_5% )
```
